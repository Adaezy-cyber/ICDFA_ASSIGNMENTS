# NexusTech Security Policy Overhaul

**GRC102 – Information Security Governance | Module 2: Developing Security Policies and Procedures**

## Project Overview

This is a scenario-based governance exercise for NexusTech Solutions, a rapidly growing mid-sized software company that expanded from 50 to 250 employees and now serves financial and healthcare clients.

The organisation's existing five-year-old **"IT Rules"** document mixes policy intent, technical configuration instructions, and vague recommendations. This creates inconsistent practices, unclear accountability, and compliance gaps.

**Role:** Information Security Manager

**Mission:** Establish a formal, structured, and maintainable security policy framework that supports security governance and readiness activities aligned with ISO/IEC 27001 and SOC 2.

> **Simulation notice:** NexusTech Solutions and the evidence in this repository are simulated for academic/portfolio purposes. No real credentials, confidential information, or production evidence are included.

## Governance Approach

The overhaul separates governance documents according to their purpose and level of authority:

**Policy → Standard → Procedure → Guideline**

- **Policy:** establishes management intent, direction, and mandatory requirements.
- **Standard:** defines mandatory, measurable requirements supporting policy.
- **Procedure:** describes the approved sequence for carrying out a process.
- **Guideline:** provides recommended good practice without the same mandatory authority as policy or standards.

## Portfolio Value

This project demonstrates how I would move an organisation from a loosely structured set of IT rules toward a maintainable security governance framework. The focus is not only on writing policies, but on connecting governance intent to operational procedures, user behaviour, evidence, review triggers, and accountability.
